## A. BUG FUNGSIONAL (prioritas tinggi)

### A1. Filter outlet di Report Shell tidak memfilter apa pun
- **Lokasi:** `addons/geprekyukss_dashboard/models/report_actions.py:188-196` (`_outlet_journal_ids`)
- **Bukti:** Kedua outlet aktif (Pallangga id 1, Mallengkeri id 2) memakai `journal_id` yang **sama** (`POSS`, id 9).
- **Dampak:** Memilih outlet apa pun menghasilkan `journal_ids=[9]` identik → laporan AFR (Trial Balance, General Ledger, Journal Ledger) **sama persis** untuk kedua outlet. Filter terlihat berfungsi tetapi no-op.
- **Rekomendasi:** Ganti basis filter ke dimensi yang membedakan outlet (analytic account/dimensi `pos.config`), atau pisahkan journal per outlet.

### A2. Instance MIS dimutasi permanen & tidak aman multi-user
- **Lokasi:** `addons/geprekyukss_dashboard/models/report_actions.py:801-865` (`_apply_mis_period`)
- **Bukti:** `_apply_mis_period()` menulis (`write`) ke record **persistent** `mis.report.instance.period`. Di DB saat ini period ber-`mode=relative`, `manual_date_from=False`, padahal default XML `mode=fix` + tanggal literal.
- **Dampak:** (1) Dua user/periode berbeda saling menimpa; (2) karena data MIS `noupdate="True"`, definisi laporan menyimpang dari source dan tidak pulih saat upgrade.
- **Rekomendasi:** Clone instance/periode ke record sementara per-request, atau hitung periode tanpa menyimpan ke DB.

### A3. Panel Waste selalu 0
- **Lokasi:** `addons/geprekyukss_dashboard/models/dashboard_data.py:689`
- **Bukti:** `stock.scrap` di Odoo 19 **tidak punya field `scrap_value`** (field hanya `scrap_location_id`, `scrap_qty`, `scrap_reason_tag_ids`). `getattr(s, "scrap_value", 0.0)` selalu 0.
- **Dampak:** Nilai waste hilang walau ada scrap.
- **Rekomendasi:** Hitung dari `scrap_qty × product cost`/valuasi stok.

## B. ANOMALI DATA / OPERASIONAL

### B1. PPN tidak pernah tercatat sama sekali (indikasi gap kepatuhan)
- **Bukti:** 9 produk POS ber-pajak 12% PPN terjual besar (TELUR KRISPI 62.197 baris, NUGGET 7.524, KEJU LUMER 7.492, TEMPE/BIJI 5.405, TAHU/BIJI 3.941, KOREK 22, RICA 13, IJO 6, BARBEQUE 2), tetapi:
  - `account_tax_pos_order_line_rel` = **0**
  - `account_move_line_account_tax_rel` = **0**
  - Laporan PPN (VAT) menghasilkan **0 baris**
- **Perlu dipastikan:** apakah pajak di-assign ke produk *setelah* order dibuat (wajar), atau POS memang tidak menerapkan pajak (bug konfigurasi). Jika PPN seharusnya dipungut, ini gap besar.

### B2. Sesi POS nyangkut (ghost session)
- **Bukti:** `pos_session` id **2203**, config Mallengkeri, state `opening_control`, `start_at` NULL, dibuat 22 Sep 2026 01:40:42 (1 detik setelah sesi 2200 ditutup). Tidak ada order.
- **Dampak:** Berpotensi "di-resume" kasir; indikasi sesi terbuka yang tidak pernah diselesaikan.
- **Rekomendasi:** Batalkan/hapus sesi hantu.

### B3. Stok negatif masif
- **Bukti:** 64 `stock.quant` negatif: ES KRISTAL −6,26 jt, AIR GALON −3,66 jt, TEPUNG MIX GEYUKSSS −1,53 jt, TEMPE −1,33 jt, MINYAK PADAT −1,18 jt, BERAS −908 rb, dst.
- **Dampak:** Valuasi persediaan & HPP berpotensi terdistorsi; bahan baku kemungkinan tidak pernah diterima di sistem.
- **Rekomendasi:** Aktifkan manajemen stok bahan baku (penerimaan) atau tandai produk sebagai non-storable bila memang tidak dilacak.

### B4. Cron penting nonaktif
- **Bukti:** `ir_cron` id 30 `Asset Management: Generate assets` **active=f** padahal modul aset dipakai (4 aset terbuka). Juga id 15 `Payment: Post-process transactions` nonaktif.
- **Rekomendasi:** Konfirmasi apakah disengaja; aktifkan bila penyusutan aset seharusnya digenerate otomatis.

### B5. Fitur level pedas belum pernah terekam
- **Bukti:** `spice_level` NULL di **semua 167.482** baris `pos.order.line`. Modul terakhir di-update 20 Sep, order terakhir 20 Sep (1 order, status `cancel`).
- **Catatan:** Hook kode `addProductToOrder` (`addons/geprekyukss_pos/static/src/overrides/models/models.js:79-117`) terlihat benar, tetapi fitur belum tervalidasi di produksi. Perlu uji end-to-end.

### B6. Fitur ikon kategori tidak dipakai
- **Bukti:** 6 `pos.category`, semuanya `pos_category_icon='none'` dan tanpa ikon kustom. Fitur berjalan tetapi kosong.

### B7. Verifikasi member WhatsApp belum ada
- **Lokasi:** `addons/geprekyukss_pos/models/res_partner.py`
- **Bukti:** Hanya field `pos_wa_number`/`pos_wa_verified`; alur OTP/provider WA masih TODO eksplisit.

### B8. Nama perusahaan masih "My Company"
- Bukan nama legal Geprekyukss.

## C. PERFORMA

- **Bukti:** 1 bulan = **18.410 baris / payload 4,76 MB** (`get_report_data`).
- **Dampak:** `ReportTable` hanya paginasi 50 baris di klien, tetapi seluruh payload tetap dikirim & disimpan di memori browser. Rentang setahun bisa berkali lipat.

- **Rekomendasi:** Cache sekali per request.

- **Lokasi:** `report_actions.py:123` (`_afr_preview`)
- **Bukti:** Membuat record wizard tiap preview tanpa cleanup, hanya mengandalkan auto-vacuum.

## D. DESAIN / LIMITASI YANG PERLU DIPERBAIKI

- **D1. Arus Kas PSAK bukan arus kas riil** — `pendanaan = delta_cash − operasi − investasi` (`dashboard_data.py:862`), sehingga laporan selalu balance by construction (plug), bukan arus kas independen.
- **D2. Filter outlet tidak berlaku di tab GL** (Beranda, HPP, Kas, Aset) — konsolidasi by design dan sudah diberi label, tetapi rawan disalahpahami karena satu dashboard menampilkan dua basis angka.
- **D3. Validasi tanggal lemah** — `date_from > date_to` diam-diam mengembalikan `has_data=false`; tanggal invalid (`""`, `"bad-date"`) melempar `ValueError` → HTTP 500.
- **D4. Penyusutan fallback kasar** — `_ops_warehouse`: bila aset tak ada di register, `dep_month = dep_period / n_bulan` (asumsi rata). `_match_dep_month` (`:709`) mencocokkan berdasarkan nama → bisa salah pasang.
- **D5. Footer tidak konsisten** — adapter `trial_balance` & `open_items` tidak mengisi `meta.totals` (GL/VAT/aged ada).
- **D6. "Filter Lanjutan" MIS** (`report_shell.js:388-408`) membuka form `mis.report.instance` tanpa `res_id` → bukan instance yang sedang dilihat.
